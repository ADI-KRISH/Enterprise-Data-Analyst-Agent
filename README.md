# Enterprise Data Analyst Agent

Natural-language business question → intent/plan → schema + KPI retrieval (RAG) → SQL generation → SQL validation → read-only PostgreSQL execution → result verification → Pandas analysis → chart → grounded answer. Exposed through a FastAPI service and a Streamlit dashboard.

> **All data is synthetic.** The `analytics` schema is generated by `database/seed.py` (fixed random seed, Indian retail, INR). Injected patterns are listed in [`database/SEED_NOTES.md`](database/SEED_NOTES.md). This is a development project, not a production deployment.

## How it stays safe and honest
- **No invented numbers.** The response LLM only sees structured results; `agents/grounding.py` checks every number in the answer against the SQL result / Pandas computations, regenerates once, then returns with `grounded: false`.
- **Read-only.** The agent connects as `analyst_ro` (SELECT on schema `analytics`). All LLM SQL is untrusted: `agents/sql_validator.py` (sqlglot) enforces a function allow-list, schema/column allow-list, single SELECT, row and `EXPLAIN` cost caps, and restricted (PII) columns never reach output. See the *Security model* in [`CLAUDE.md`](CLAUDE.md).
- **Guardrails.** `input_guard` refuses off-topic / write / injection / PII requests; `output_guard` blocks restricted values, SQL errors and internals.
- **Relative dates** ("last quarter") resolve against `ANCHOR_DATE = max(order_date)` (2026-09-30), not the system clock ([`reporting_policies.md`](retrieval/docs/reporting_policies.md)).
- Errors returned to users are generic plus a `request_id`; details go to `logs/audit.jsonl`.

## Setup
Requires Python 3.11 and Docker.

```bash
python -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
cp .env.example .env            # fill in passwords, API_KEY and OPENROUTER_API_KEY
docker compose up -d db         # Postgres 16; applies schema.sql + roles.sql on first run
python -m database.seed         # load synthetic data (admin URL; truncates and reloads)
python -m retrieval.data_dictionary
python -m retrieval.build_index # local embeddings (fastembed), no API key needed
```

LLMs are called through [OpenRouter](https://openrouter.ai) (`OPENROUTER_API_KEY`); models are configurable via `LLM_MODEL_*` in `.env`.

## Run
```bash
python -m app.cli "total revenue last quarter"      # terminal
uvicorn app.main:app --reload                       # API on :8000
streamlit run dashboard/streamlit_app.py            # UI on :8501 (uses API_URL, API_KEY from env)
docker compose up -d                                # db + api + dashboard
```

```bash
curl -X POST localhost:8000/analyze -H "X-API-Key: $API_KEY" -H 'content-type: application/json' \
     -d '{"question": "revenue by region last quarter"}'
```

| Route | Auth | Notes |
|---|---|---|
| `POST /analyze` | `X-API-Key` | `question` ≤ 500 chars (422), per-IP rate limit (429), request timeout (504) |
| `GET /schema` | `X-API-Key` | allow-listed tables/columns only |
| `GET /health` | none | |

## Tests and evaluation
```bash
pytest -q                 # unit + security tests (live-DB tests skip if Postgres is down; no network LLM calls)
python -m eval.run_eval   # needs a working OPENROUTER_API_KEY; writes eval/results/<timestamp>.json
```
`eval/questions.yaml` holds 15 analytics questions with gold SQL, 3 borderline analytics questions that must not be refused, and 9 guardrail cases. `run_eval` reports guardrail block rate (+ reason accuracy) and false-refusal rate separately, plus execution, gold-result match, grounding and latency. **No accuracy or latency figures are quoted here**; the only source of truth is the saved files in `eval/results/`.

## Layout
`app/` FastAPI + LangGraph + LLM client · `agents/` graph nodes, validator, executor, guards · `retrieval/` KPI/policy docs, data dictionary, vector index · `database/` schema, roles, seed, allow-list · `analytics/` Pandas analysis · `visualization/` Plotly specs built by our code · `dashboard/` Streamlit · `eval/` · `tests/`.

## Demo
With the API and dashboard running (`docker compose up -d`, or the two commands above), run the scripted walkthrough:

```bash
python -m demo.run_demo     # health/auth/size checks, KPI, breakdown+chart, ranking, trend, "why" diagnosis, borderline and guardrail cases
```
